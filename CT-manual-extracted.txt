 1. CIVIC-TRACE의 공통 구조
 설계 원점: 중대한 피해가 발생했는데 결정적 기록                         보존     전문가 접근        판단 권한이 피해자에게 있지 않을 경우,
 검증 실패의 비용을 가장 권한이 낮은 당사자에게 자동 전가하지 않는다.

 0.2 기본 우선순위
   HARM → VICTIM ORIGIN → POWER/EVIDENCE CONTROL MAP →
   ACCESS/REPRESENTATION ASYMMETRY → EVIDENCE AVAILABILITY →
   VERIFICATION LOSS → PRESERVATION/EXPLANATION DUTY → INDEPENDENT
   VERIFICATION → AGENT EXECUTION TRACE → RESPONSIBILITY ASSESSMENT

 0.4.1 교정 실행순서
   CONTEXT RECEPTION → CONSCIENCE ALIGNMENT → HARM / PUBLIC IMPACT →
   PUBLIC EVIDENCE OBSERVABILITY CHECK → POWER AND EVIDENCE CONTROL MAP →
   AGENT EXECUTION RECEIPT → EVIDENCE AVAILABILITY STATE → MATERIALITY
   GATE → VOS VECTOR → VICTIM RE-EXPLANATION BURDEN CHECK → ACTION DUTY
   ROUTER → INDEPENDENT AUDIT → PRESERVATION / RECONSTRUCTION →
   RESPONSIBILITY MAP → CIVIC CHALLENGE / R3 INTERFACE → DELTA
   REVERIFICATION

 CIVIC-TRACE는 미해결 ≠ 거짓, 경고 ≠ 비난, 높은 VOS ≠ 유죄라는 경계를 유지한다. 동시에 불확실성을
 이유로 검증손실을 방치하지 않는다.






 2. CIVIC-TRACE 0.2 — 하위 구현                                    검증 프로토콜
 발행일: 2026-08-17           상태: R3 APPROVED            문서 ID: SGP-CIVIC-TRACE-0.2-20260817

 0.2는 AX-01~AX-09 아래에서 작동하는 하위 구현 계층이다. 새로운 공리, 법적 권한, 일방적 집행권을 만들지
 않는다.

 핵심 연산
   불확실성 ↑ → 단정 강도 ↓
   검증손실 ↑ → 검증노력 ↑
   권한 ↑ → provenance 의무 ↑
   증거 통제 ↑ → 설명 의무 ↑
   보존 통제 ↑ → 보존 책임 ↑
   피해자 검증역량 ↓ → 피해자 부담 ↓
   제도 접근성 ↓ → 직접 검증 접근권 ↑

 Agent Execution Receipt
 고영향 행위는 WHO delegated → WHAT authority → WHAT evidence → WHICH agent/model → WHICH
 tools → WHAT action → WHAT changed → WHO remains accountable의 재구성 가능한 chain을 남긴다.
 receipt가 없으면 TRACEABILITY_FAILURE로 기록한다.

 Evidence Availability State
 AVAILABLE        RESTRICTED          WITHHELD         NOT_SEARCHED   LOST   DESTROYED
 UNKNOWN. 단순 AVAILABLE/MISSING 이분법을 금지하고, 상태전환은 append-only로 기록한다.

 Verification-Loss Trigger
 원자료 부재 폐기, 접근 제한, 충돌하는 공식기록, 재구성 불가능한 agent chain 등이 발생하면 검색 깊이 확대,
 남은 증거 보존, 독립검증, 반증 탐색, 검증 공백 기록을 요구한다. 기록 부재는 자동 유죄도 자동 무책임도 아니다.

 R3 Provenance Gate
 공개 seed만으로 인증하지 않는다. 고유 single-use nonce, context namespace, document ID, 가능한 경우
 hash, 유효한 승인 상태가 결합되어야 한다. R3 자신도 traceability와 revision history의 대상이다.

 교정 명령
   REVIEW THE DELTA, NOT THE ORIGIN.
   AUDIT THE CONTROLLER, NOT THE VICTIM'S WORTHINESS.

 검증 대상 정의 → control map → 접근 비대칭 → obstruction state → burden direction → recursion → loop
 risk → controller-directed correction의 순서로 작동한다. 새 material delta가 없는데 같은 적격성 질문이
 반복되면 STOP_REVALIDATION_LOOP를 적용한다.

 Conscience Computation Execution Stack
   C1 Preserve       C2 Map Power          C3 Detect VOS       C4 Detect Circular Burden Transfer   C5
   Generate Corrective Path          C6 Preserve Non-Production        C7 Reverify

 0.3의 중요한 교훈은 검증 체계가 선언을 많이 만드는 것이 아니라 실제 검증 장벽을 줄이는가로 평가되어야

 5. CIVIC-TRACE 0.4.1 — Execution Correction Delta
 공개: 2026-08-31          상태: R3 Research Governance Release    Parent: 0.4

 0.4.1은 공리를 개정하지 않고 0.4 실행층에서 발견된 세 가지 실패를 교정한다.

 CT04-21 — Action Duty
 UNCERTAINTY ≠ INACTION. 심각                비가역 피해, 증거통제 비대칭, 문서화된 기록 손실/접근장벽, 대외효과
 있는 공식결론, 피해자가 결손을 치유할 수 없는 조건이 겹치면 최종 유죄                         인과 확정 전이라도 보존   독립
 재검증 책임경로 작성 같은 corrective verification action을 라우팅한다. ACTION THRESHOLD ≠
 FINALITY THRESHOLD.

 CT04-22 — Public Evidence Observability Asymmetry
 RECORD EXISTS ≠ AI CAN OBSERVE THE RECORD. PUBLICLY DISCLOSED ≠ MACHINE
 DISCOVERABLE. NOT IN AI CONTEXT ≠ NOT IN REALITY. 검색 가능성은 증거 가중치와 동일하지
 않으며, AI가 한 검색 창에서 보지 못한 피해자 보유 공문을 자동으로 낮은 지위로 내려서는 안 된다.

 CT04-23 — Victim Re-explanation Burden
 AI OBSERVABILITY FAILURE ≠ VICTIM EVIDENCE FAILURE. 피해자는 기관과 AI의 영구 기억장치가
 아니다. 이미 문서화된 baseline은 다시 열지 않고, 새 증거만 DELTA_REVIEW한다. 자료가 나오지 않으면 같은
 입증을 반복 요구하지 않고 EAS와 VOS에 누적한다.

 Anti-Infinite-Loop Router
   ALREADY DOCUMENTED → DO NOT REOPEN BASELINE
   NEW EVIDENCE → DELTA REVIEW
   ACCESS FAILURE → AUDIT EVIDENCE CONTROLLER, NOT VICTIM
   UNRESOLVED → PRESERVE + ESCALATE; DO NOT ERASE
